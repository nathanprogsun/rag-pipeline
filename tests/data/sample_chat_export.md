# 用 AI 工具快速吃透开源项目的实战方法论

以 deer-flow(字节开源的多 Agent 框架)为例,这是一套经过验证的 **"AI 辅助 + 人脑建模"** 的项目学习法。核心思路是:让 AI 做"信息搬运和解释",人脑专注于"建模、判断和创新"。

---

## 一、整体心法:四阶段漏斗

```
广度扫描 → 关键路径深挖 → 跑通+魔改 → 反向输出
   (1-2h)      (1-2天)        (2-3天)       (持续)
```

不要一上来就读源码,先用 AI 把项目"切片"成可消化的信息块。

---

## 二、阶段一:鸟瞰式扫描(0.5 - 2 小时)

### 1. 让 AI 一键生成项目地图

在项目根目录启动 Claude Code:

```bash
cd deer-flow
claude
```

然后在对话里输入:

> 请阅读整个项目, 生成一份**架构说明书**,要求:
> 1. 用 Mermaid 图画出整体架构(Agent / Node / Graph 关系)
> 2. 列出核心模块及其职责(表格形式)
> 3. 标出 3 个最值得先读的"骨干文件",并说明为什么
> 4. 梳理清楚请求从进入到返回的完整数据流

Claude Code 会自动调用工具读文件、跑 grep,直接给你一份"项目说明书"。

### 2. 利用 `/init` 自动生成 CLAUDE.md

```
/init
```

这个命令会扫描项目并生成 `CLAUDE.md`,把项目结构、技术栈、约定写进项目级上下文。**后续所有对话都会自动带上这份上下文**,相当于给 AI 装了一个"项目记忆"。

### 3. 补充项目元信息

在 CLAUDE.md 手动补充:

- 你的学习目标(比如"我想搞懂 multi-agent 编排")
- 你关心的模块(比如"工具注册机制")
- 你打算魔改的方向(比如"接入公司内部 LLM")

---

## 三、阶段二:关键路径深挖(1 - 2 天)

### 1. 锁定"骨干文件"集中攻克

deer-flow 的骨干一般是:

- 入口文件(`main.py` / `app.py`)
- Agent 编排核心(`graph.py` / `workflow.py`)
- LLM 封装层
- 工具/Tool 注册与调用层

**不要平行读所有文件**,而是**沿一次完整调用纵向追踪**:

> 请追踪一个用户请求的完整生命周期:
> 1. HTTP 请求从哪个入口进来?
> 2. 如何路由到对应的 Agent / Graph?
> 3. 工具调用是怎么注册、匹配、执行的?
> 4. 最终响应如何组装返回?

### 2. 用"费曼技巧"反向提问

读完后, 让 AI 反过来考你:

> 基于我对 [某模块] 的理解(我下面会描述),请扮演资深架构师, 指出我理解中的**错误、遗漏和过度简化**。

你描述一遍, AI 追问细节, 逼你把模糊理解变成可复述的模型。

---

## 四、阶段三:跑通 + 魔改(2 - 3 天)

### 1. 先跑通, 再优化

```bash
# 让 AI 帮你解决环境问题
claude
> 我执行 `poetry install` 时报错如下:[贴日志]。请诊断并修复
```

### 2. 带着问题魔改

挑 3 个有代表性的微调:

| 类型 | 示例 | 学习目标 |
| --- | --- | --- |
| **改配置** | 换默认模型 / 调 timeout | 理解配置分层 |
| **改 prompt** | 调整 planner 的 system prompt | 理解 prompt 注入点 |
| **加新能力** | 接入一个新的 Tool(比如发邮件) | 掌握扩展机制 |

---

## 五、阶段四:反向输出, 固化理解

### 1. 让 AI 当"严厉 reviewer"

你写完一段总结 / 博客 / 内部分享后:

> 我写了一份关于 deer-flow 架构的学习笔记 [贴内容]。请以**资深开源贡献者**的视角评审:
> - 哪些结论是错的或过度简化
> - 哪些细节遗漏了但很关键
> - 如果我要提 PR, 应该从哪个模块切入

### 2. 写一个"自己实现的迷你版"

> 请基于我对 deer-flow 的理解,帮我设计一个**精简到 200 行的 mini-deer-flow**:
> - 保留 multi-agent 编排的核心机制
> - 砍掉所有非必要抽象
> - 用 Python 实现, 附 README 说明与原项目的映射关系

## 六、效率倍增的 5 个小技巧

| 技巧 | 做法 | 收益 |
| --- | --- | --- |
| **CLAUDE.md 持续更新** | 每次有重大发现, 追加到文件 | 上下文不断层, 跨会话可续接 |
| **用 Plan Mode 规划** | Shift+Tab 进入规划模式再动手 | 减少返工 |
| **@file 精准引用** | 对话里 `@graph.py` 锁定文件 | 减少全项目扫描 |
| **保存常用 prompt** | 把"解释这段代码""生成调用链"做成斜杠命令 | 一键复用 |
| **对比竞品实现** | 让 AI 对比 langgraph / autogen 同类设计 | 建立设计判断力 |

---

## 七、常见误区

❌ **"我先把所有源码读完再说"** —— 会迷失在细节里,1 周还没动手跑过

✅ **先跑起来, 带着具体问题去读**

❌ **让 AI 直接解释每一行代码** —— 信息密度太低

✅ **让 AI 解释"为什么这么设计 / 有什么替代方案"**

---

## 一句话总结

> **让 AI 干它擅长的(检索、搬运、解释、生成样板),把脑子留给只有人能干的(建模、判断、创造、表达)。**

按这个四阶段走,3-5 天可以做到对一个中等规模开源项目**能跑、能改、能讲清楚**,7-10 天可以做到**能提交有质量的 PR**。
